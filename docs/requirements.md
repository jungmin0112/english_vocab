# 적용 요구 사항

상태: 이 프로젝트의 실제 구현·검증 기준

확인일: 2026-11-14

## 적용 범위와 근거

영어 단어 암기 및 복습 관리가 필요한 학생을 위한 Python 콘솔 MVP를 대상으로 한다. 사용자 한 사람의 기록을 관리하며 계정 구분은 제공하지 않는다. 직접 등록한 단어의 퀴즈 결과와 자기평가를 이용해 FSRS 학습 상태와 복습 예정 시기를 관리한다.

이 문서의 F-01~F-09와 예외 동작을 개발 및 검증에 적용한다. 요구 사항이 정해졌다는 사실은 기능 구현·시험 완료를 뜻하지 않는다. 상세 설계의 미결정 항목은 별도로 구분한다.

출처는 [1차 요구 분석 명세서](https://app.notion.com/p/409097f2b03b81f59a0cc114c25dff4a), [1차 개발 계획서](https://app.notion.com/p/409097f2b03b81b1b2e4d270524e0288), [문서 생성 기준](https://app.notion.com/p/418097f2b03b81d38877c2c3baef84e1)이다. 노션 요구 분석 원본은 팀원 검토 전 1차 초안으로 기록되어 있었으나, 2026-11-14 사용자가 이 로컬 문서를 실제 적용할 요구 사항으로 지정했다. 변경 시 사용자 확인을 받아 관련 설계·검증 기준도 함께 갱신한다.

## 기능 요구 사항과 검증 기준

### F-01 단어 등록

- 사용자가 영어 단어와 하나 이상의 한국어 뜻을 직접 등록한다.
- 영어 대소문자를 무시하여 중복을 판단한다. 기존 단어이면 뜻을 추가한다.
- 한국어 뜻의 띄어쓰기 차이를 무시하여 동일한 뜻의 중복 등록을 막는다.
- 검증: `Apple` 등록 후 `apple`에 다른 뜻을 추가하면 같은 단어에 뜻이 추가된다. `돌아가다`와 `돌아 가다`는 중복 뜻으로 처리된다.

### F-02 단어 조회

- 등록된 단어와 뜻을 전체 목록으로 표시한다.
- 목록에 검색 필터를 적용하여 원하는 단어를 찾을 수 있다. 검색 대상은 내부 등록 데이터다.
- 검증: 등록 목록과 뜻을 확인할 수 있고 필터가 등록 데이터 안에서 동작한다. 구체적인 검색 일치 기준과 조작 방식은 상세 설계에서 결정한다.

### F-03 퀴즈 진행

- 선정된 단어를 한 문제씩 보여주고 한국어 뜻을 주관식으로 입력받는다.
- 한 회차는 최대 15문제로 고정하며 같은 단어를 중복 출제하지 않는다.
- 대상 선정은 F-09를 따른다. 문제 수 사용자 지정은 후순위다.
- 검증: 대상이 15개 이상이면 15문제, 15개 미만이면 가능한 문제만 진행하며 한 회차의 출제 단어가 중복되지 않는다.

### F-04 자동 채점

- 입력 답이 등록된 여러 한국어 뜻 중 하나와 일치하면 정답이다.
- 한국어 띄어쓰기 차이를 무시한다. 빈 입력과 미등록 동의어는 오답이다.
- 각 문제의 결과를 즉시 표시한다.
- 검증: 여러 뜻 중 하나 및 띄어쓰기만 다른 답은 정답이다. 빈 답과 의미가 비슷해도 등록되지 않은 답은 오답이며 문제별 피드백이 나타난다.

### F-05 퀴즈 결과

- 종료 후 전체 문제 수·정답 수·오답 수를 표시한다.
- 단어별 정답 여부와 사용자가 입력한 답을 표시한다.
- 오답에는 등록된 실제 뜻을 함께 표시한다.
- 검증: 정답 수와 오답 수의 합이 전체 문제 수와 같고, 단어별 입력 답·정오 결과 및 오답의 등록 뜻을 확인할 수 있다.

### F-06 자기평가

- 퀴즈 종료 후 정답 단어는 Good을 기본값으로 표시한다.
- 사용자는 필요한 정답 단어만 Hard 또는 Easy로 변경할 수 있다. 변경하지 않으면 Good을 유지한다.
- 오답 단어는 Again을 자동 적용한다.
- 최종 평가 확정 후 복습 계산에 반영한다.
- 검증: 정답 기본값은 Good, 오답은 Again이며 정답의 Hard/Easy 변경이 가능하다. 확정한 평가가 F-07 계산에 사용된다.

### F-07 복습 일정 계산

- FSRS 라이브러리로 단어별 학습 상태를 갱신하고 다음 복습 예정 시기를 계산한다.
- 출제 여부는 정확한 시각이 아닌 날짜를 기준으로 판단한다.
- 기록에는 학습 시각과 복습 예정 시각 등 시간 정보를 보존한다.
- 검증: 확정 평가로 FSRS 상태와 다음 복습 시기를 계산할 수 있다. 오늘 날짜에 예정된 단어는 시각이 아직 지나지 않았더라도 복습 대상이며, 저장·복원 시 시각 정보가 유지된다.

### F-08 학습 기록 저장

- 프로그램 시작 시 기록을 자동으로 불러온다.
- 단어 등록·수정 시 자동 저장한다.
- 퀴즈 종료 후 자기평가 확정에 따라 갱신된 학습 상태를 자동 저장한다.
- 종료·재실행 후에도 단어, 평가 결과, FSRS 학습 상태와 복습 시각을 복원한다.
- 검증: 단어 등록·수정 및 자기평가 확정 후 종료·재실행하면 해당 변경과 학습 상태가 유지된다.

### F-09 맞춤 출제 대상 선정

- 복습 예정일이 오늘 또는 과거인 단어를 우선 선정한다.
- 복습 대상 중 가장 오래 밀린 단어부터 선택한다.
- 남은 문제 수는 미학습 신규 단어로 채우며 전체는 최대 15개다.
- 대상이 부족하면 가능한 수만 선정한다. 복습 미도래 단어는 강제로 추가하지 않는다.
- 검증: 복습 대상이 15개를 넘으면 오래 밀린 순으로 15개를 선정한다. 복습 대상이 3개이고 신규가 4개이면 7개만 선정하며, 나머지 등록 단어의 복습일이 미래이면 추가하지 않는다.

## 책임 구분과 예외 동작

- F-09는 출제할 단어를 결정한다. F-03은 선정된 문제를 진행하고, F-04는 입력 답의 정오를 판단한다.
- 등록 단어가 없으면 퀴즈를 진행하는 대신 단어 등록을 안내한다.
- 등록 단어가 있어도 복습 대상과 신규 단어가 모두 0개이면 현재 출제 가능한 문제가 없음을 안내한다.
- 복습 대상과 신규 단어를 합쳐도 15개 미만이면 가능한 단어만 출제한다.
- 비교용 문자열과 화면 출력용 표기는 구분할 필요가 있다. 출력 표준과 구현 방식은 미결정이며 자동 문법 교정은 요구 사항에 포함하지 않는다.

## 품질 요구와 개발 제약

- 기록 보존: 종료 후에도 F-08의 기록을 복원할 수 있어야 한다.
- 유지보수성: 기능별로 코드를 분리해 다른 기능의 수정 범위를 줄인다.
- 확장성: 향후 콘솔/GUI, JSON/SQLite 교체와 외부 단어장 연동을 고려하되 구체적 구현은 상세 설계에서 결정한다.
- 초기 기술 방향: Python, VS Code, 콘솔, Py-FSRS, JSON 저장을 우선 적용한다. 공통 개발 환경은 Python 3.11 계열과 `requirements.txt`를 따르며 라이브러리 수준의 검증 결과는 [설계 문서](design.md)에 기록한다. 앱 기능과의 통합은 별도 검증한다.

## MVP 제외·후순위 범위

- 문제 수 사용자 지정, 별도 단어 중요도 산정 및 중요도 기반 출제
- 외부 단어장·온라인 사전 연동, 외부 자료를 활용한 채점 개선
- GUI, 기본 내장 단어장, 상세 통계·시각화, 계정 관리
- 전체 학습 기록 초기화, 자체 FSRS 가중치 조정
- SQLite 전환 등 기술 확장

## 상세 설계에서 결정할 사항

- 공통 단어 데이터 구조, 비교용 문자열과 화면 출력 표기 규칙
- 목록 필터의 검색 일치 기준·콘솔 조작 흐름, 자기평가 입력 UI
- 모듈별 함수의 입력·출력·오류 처리·호출 계약
- JSON 형식과 FSRS 상태·학습 시각·복습 예정 시각의 저장·복원 구조
- 날짜 판단에 사용할 시간대, 신규 단어 및 동일 복습일 단어 간 선정 순서
- 최초 실행의 저장 파일 부재, 손상 파일, 저장 실패, 퀴즈 중단에 대한 처리
- 구체적인 단어 수정 범위·조작 방식, 유효하지 않은 등록 입력 처리
- 추가 지원할 Python 버전·운영체제, 프로젝트 테스트 구성·실행 명령

마지막 목록은 구현에 앞서 검토할 설계 질문이며, 아직 합의된 동작이나 추가 기능 요구로 취급하지 않는다.

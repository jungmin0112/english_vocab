# 시스템 설계와 모듈 인터페이스

확인일: 2026-11-14

상태: 기능별 모듈화 원칙은 적용하며, 아래 파일 구성은 초기 설계안이다. 상세 데이터 구조와 함수 인터페이스는 설계 필요 상태다. 구현 동작은 [적용 요구 사항](requirements.md)을 따른다.

## 설계 근거와 현재 구현 비교

[1차 개발 계획서](https://app.notion.com/p/409097f2b03b81b1b2e4d270524e0288)와 [최신 문서 생성 기준](https://app.notion.com/p/418097f2b03b81d38877c2c3baef84e1)을 바탕으로 한다. 기능별 책임을 분리하여 UI·저장 방식 변경의 영향을 줄이는 것이 원칙이다. 파일 수와 경계는 구현 중 검토할 수 있다.

현재 작업 트리에 Python 소스가 없어 모듈의 실제 함수·자료 구조·연결 방식은 확인할 수 없다. 다른 작업 트리나 팀원의 완료 상태는 미확인이다.

| 초기 파일안 | 역할 | 연결 요구 사항 | 현재 상태 |
| --- | --- | --- | --- |
| `main.py` | 실행 진입점, 콘솔 메뉴와 전체 흐름 연결 | 전체 흐름, 시작 시 F-08 | 파일 없음 |
| `words.py` | 단어 등록·중복 처리·조회·검색 | F-01, F-02 | 파일 없음 |
| `quiz.py` | 문제 진행·답 입력·채점·결과·자기평가 | F-03~F-06 | 파일 없음 |
| `review.py` | FSRS 상태 갱신·복습 시기 계산·출제 대상 선정 | F-07, F-09 | 파일 없음 |
| `storage.py` | 단어·학습 상태의 저장·복원 | F-08 | 파일 없음 |

이 표는 책임의 초기 배치이며 구체적인 함수명이나 호출 계약을 확정하지 않는다. 단어·학습 상태의 저장 시점은 요구 사항을 따르되 어느 모듈이 저장 호출을 조율할지는 설계가 필요하다.

## 요구 사항에 따른 데이터 흐름

```text
프로그램 시작 → 기록 자동 불러오기 → 콘솔 메뉴
  ├─ 단어 등록·수정 → 중복 처리 등 단어 관리 → 자동 저장
  ├─ 등록 단어·뜻 조회 및 내부 검색 필터
  └─ 퀴즈 요청
       → 복습 대상(오래 밀린 순) + 남는 수만큼 신규 단어 선정
       → 최대 15문제 진행 → 답 입력·채점·즉시 피드백
       → 회차 결과 표시
       → 정답 Good 기본 / 필요한 정답 Hard·Easy 변경 / 오답 Again
       → 평가 최종 확정 → FSRS 상태·복습 시기 갱신 → 자동 저장
```

출제 가능한 대상이 없을 때는 요구 사항의 안내 동작을 따른다. 출제 대상 선정과 문제 진행·채점의 책임은 구분한다. 위 흐름은 기능의 순서이며 실제 파일 간 호출 순서를 확정한 것은 아니다.

## 데이터에 담아야 할 의미

| 정보 | 요구되는 의미 | 상세 설계 상태 |
| --- | --- | --- |
| 영어 단어와 한국어 뜻 목록 | 영어 대소문자 및 한국어 띄어쓰기 차이를 반영한 중복 처리 | 키 이름·자료형·식별 방식 설계 필요 |
| 비교용 표기와 화면 표시 | 중복 판단·채점과 화면 출력의 구분 | 정규화·표준 출력 규칙 설계 필요 |
| 회차별 답과 정오 결과 | 즉시 피드백 및 종료 결과 표시 | 회차 자료 구조·저장 범위 설계 필요 |
| 확정 평가 결과 | Again·Hard·Good·Easy에 따른 학습 반영 | 결과 저장 구조 설계 필요 |
| FSRS 학습 상태 | 다음 학습에서 이어서 복습 계산 가능 | 라이브러리 JSON 복원 검증 완료, 앱 저장 구조 설계 필요 |
| 실제 학습 시각·복습 예정 시각 | 시간 정보를 보존하며 출제는 날짜로 판단 | 저장 형식·시간대 설계 필요 |

이 표는 필요한 정보의 의미를 정리한 것이다. JSON 키, 파일명, 클래스·딕셔너리 구조 또는 FSRS API를 정의한 스키마가 아니다.

## 모듈 통합 전 확인할 계약

퀴즈 담당과 단어 저장·관리 담당은 아래 사항을 함께 확인해야 한다. 함수명·시그니처·자료형은 아직 확정하지 않는다.

| 연결 지점 | 확인할 내용 | 완료 기준 |
| --- | --- | --- |
| 단어 관리 → 퀴즈·복습 | 단어 식별, 표시할 영어, 등록 뜻 목록, 학습 상태 전달 방식 | 두 모듈이 같은 샘플 데이터를 읽을 수 있음 |
| 출제 선정 → 퀴즈 | 선정 결과의 자료 구조·순서·최대 개수, 대상 없음 표현 | 복습 우선·최대 15개·중복 없음 조건을 확인함 |
| 퀴즈 → 복습 | 단어 식별과 최종 확정 평가의 전달 방식·반영 시점 | 확정 평가가 해당 단어의 복습 계산에 연결됨 |
| 단어 관리·복습 → 저장 | 저장을 호출할 주체, 저장 대상 상태, 실패 전달 방식 | 등록·수정·평가 확정 후 저장 흐름을 확인함 |
| 저장 → 프로그램 | 불러온 데이터의 형식, FSRS 상태 복원, 파일 부재·손상 처리 | 재시작 후 단어·평가·학습 상태·시각을 복원함 |

신규 단어의 상태 표현, 날짜 판단 시간대, 동률 선정 순서, 중단·잘못된 입력 처리 등은 요구 사항의 미결정 목록과 함께 검토한다. 실제 코드가 들어오면 이 문서와 차이를 기록하고, 계약 변경의 이유와 영향을 설명하여 사용자 확인 후 반영한다.

## 기술 검증과 임시 대응 후보

- 공통 개발 기준은 Python 3.11 계열과 `fsrs==6.3.2`다. 새 작업 트리에서는 README의 절차로 독립된 `.venv`를 구성한다.
- JSON은 우선 저장 방향이며 파일 경로·스키마·직렬화 규칙은 미정이다.
- 임시 파일 저장 후 교체·백업은 계획서의 임시 후보다. 채택 여부와 복구 동작은 검토가 필요하다.
- SpacedRepPy, SQLite, GUI 전환은 미검증 대안·확장 후보이며 현재 구현 계약이 아니다. SM-2 전환은 알고리즘 목표 변경이므로 별도 합의가 필요하다.

## 환경 검증 기록

2026-11-14 Windows의 이 작업 트리에서 Python 3.11.2로 `.venv`를 새로 생성하고 `requirements.txt`를 설치했다. 전역 패키지와 분리된 환경임을 확인했으며, FSRS 6.3.2와 간접 의존성 typing_extensions 4.16.0이 설치되었다. `python -m pip check`는 의존성 충돌 없이 통과했다. Python 경로는 README의 `.venv` 전용 경로를 사용했다.

임시 인라인 실행으로 다음 라이브러리 동작을 확인했다. 프로젝트 테스트 파일이나 개인 데이터는 생성하지 않았다.

- `Scheduler(enable_fuzzing=False)`와 고정된 UTC 학습 시각으로 Again·Hard·Good·Easy를 각각 처리하여 다음 복습 시각이 계산됨을 확인했다.
- `Scheduler`, `Card`, `ReviewLog`의 `to_json()` / `from_json()` 저장·복원이 동작하고 카드·로그 정보 및 시각이 유지됨을 확인했다.
- 복원한 카드로 후속 복습 계산이 가능함을 확인했다.
- `.venv/`, `/data/`와 `.env`가 Git 제외 규칙에 해당함을 확인했다.

검증 근거 API: [FSRS 6.3.2 공식 배포 문서](https://pypi.org/project/fsrs/6.3.2/). 이 결과는 라이브러리 수준의 환경 확인이며 앱의 F-07·F-08 구현 완료를 뜻하지 않는다. 앱 저장 스키마, 출제 날짜의 시간대 정책과 통합 검증은 여전히 설계·개발 대상이다. 다른 Python 버전·운영체제에서는 이번에 실행 검증하지 않았다.
